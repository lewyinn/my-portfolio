## Kenapa MDX, bukan CMS terpisah?

Untuk website personal maupun blog dokumentasi teknis, menjalankan headless CMS eksternal sering kali membuat alur publish jadi lambat. Dengan menyimpan artikel langsung sebagai file MDX di dalam repository Git, penulisan teks, komponen interaktif React, dan riwayat revisi ikut tercatat rapi tanpa server tambahan.

<Callout title="INTI SINGKAT">
  Semakin ringkas jalur publish artikel tanpa database atau layanan luar, semakin cepat ide teknis
  berubah menjadi halaman statis yang siap dirayapi Google.
</Callout>

## Alur Kerja Pipeline Konten

Setiap artikel cukup berupa satu file `.mdx` dengan metadata frontmatter di bagian paling atas:

```mdx title="content/blog/nextjs-mdx-seo-blog.mdx"
---
title: "Bikin Blog SEO-Friendly Pakai Next.js dan MDX"
description: "Cara setup konten statis cepat dengan metadata dinamis."
date: "2026-11-03"
tags: ["Next.js", "MDX", "SEO"]
---

Mulai tulis isi artikel di sini...
```

Saat build berjalan, schema Velite memvalidasi seluruh frontmatter agar tidak ada tanggal atau deskripsi yang terlewat, mengompilasi MDX menjadi JSX, lalu Next.js App Router menghasilkan HTML statis beserta tag OpenGraph dan canonical URL.
